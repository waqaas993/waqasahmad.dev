# Warping Static-Site Generators (wrun site:*) — v1

---

## Overview

This specification defines **v1 of a deterministic, local-first static-site scaffold and generator workflow** for small teams (2–10), with a lightweight solo-developer mode.

The system extends the existing `wrun` CLI with `site:*` commands that scaffold a ready-to-deploy **GitHub Pages–compatible static site** (repo-root HTML), then generate new work/project pages **without rewriting user-authored HTML**.

This spec intentionally separates:

- **Generator responsibilities** (structure, data, safety)
- **Template/UI responsibilities** (layout, visuals, theme, icons)

---

## Goals

- Provide a deterministic, low-ceremony scaffold for a portfolio/static site.
- Support repeatable growth (e.g. `/work/<slug>/`) without refactors.
- Keep the workflow local-first (no cloud dependency).
- Ensure identical output across machines and runs.
- Keep pages simple: HTML + Tailwind CDN + tiny vanilla JS.
- Enforce strict ownership boundaries (no silent rewrites).

---

## Non-Goals

- Open-source community workflows.
- Multi-agent orchestration.
- Markdown processing, frontmatter DSLs, routing abstractions, or CMS behavior.
- Framework lock-in or JS-heavy generation.
- Regenerating or rewriting existing user-authored HTML.
- Supporting `file://` rendering of the work list at all costs.
- Theme systems or design tokens inside generators.

---

## Core Principles

- **House rules > cleverness**
- **Determinism over convenience**
- **Generators create once; humans own thereafter**
- **No hidden normalization or inference**

---

## Determinism & Safety Rules

- Generators MUST produce the same outputs for the same inputs.
- Generators MUST NOT infer values not explicitly provided.
- JSON output MUST be stable and diff-friendly.
- On validation failure or conflict, **no files may be changed**.
- User-authored HTML MUST NEVER be overwritten.

---

## Local-First Constraints

- All commands run locally.
- No build step required.
- Output deploys directly to GitHub Pages.
- Tailwind loaded via CDN (v1).
- Vanilla JS only.

---

## URL & File Conventions

- Directory + `index.html` routing ONLY:
  - `/work/<slug>/index.html` → `/work/<slug>/`
- All internal links MUST:
  - Use trailing slashes
  - Be absolute-from-root
- Anchors MUST be stored as `/#contact`, never `#contact`.

---

## Slug Rules

- Strict kebab-case only:
  - `a–z`, `0–9`, `-`
- Must start with letter or number
- No trailing `-`
- No consecutive `--`
- Length: 2–60 characters
- Invalid slug → hard error, no changes

---

## HTTP vs file:// Rendering

- `/work/index.html` MUST load `/assets/data/work.json` via `fetch()`
- When opened via `file://`:
  - Page loads normally
  - Project list shows a small hint:

    > Run `python3 -m http.server` to preview project list.

  - No console errors

---

## Configuration

### warp.config.json

- Location: repo root
- Generated by: `wrun site:init`
- Read-only for all generators after creation

#### Required fields

- `site_title`
- `site_description`
- `base_url`
  - MUST start with `https://`
  - MUST NOT end with `/`
- `author_name`

#### Practical fields (v1)

- `cname`
- `nav` (array of `{ label, href }`)
- `seo_defaults`
  - `og_title`
  - `og_description`
  - `og_image` → `/assets/images/og.png`
  - `favicon` → `/assets/images/favicon.png`
- `contact_email`
- `socials`
  - `github`
  - `linkedin`

Generators MUST NOT mutate this file after `site:init`.

---

## Data Model

### Work Data File

- Path: `/assets/data/work.json`
- Type: JSON array
- Append-only
- Order = display order
- Duplicate slug → hard error

#### Entry Schema (v1)

Required:

- `slug`
- `title`
- `summary`

Optional:

- `tags` (array)
- `links` (object)
  - MUST include `page` = `/work/<slug>/`
- `metrics` (array)

---

## Repository Layout (v1)

### Generator-managed (Warp may create/overwrite ONLY under /assets/* with --force)

- `/index.html`
- `/work/index.html`
- `/work/<slug>/index.html`
- `/warp.config.json`
- `/CNAME`
- `/.nojekyll`
- `/robots.txt`
- `/sitemap.xml`
- `/.gitignore`
- `/README.md`

- `/assets/data/work.json`
- `/assets/js/work.js`
- `/assets/css/site.css`
- `/assets/images/og.png`
- `/assets/images/favicon.png`

### Human-managed (Warp MUST NOT touch)

- `/images/`

## CLI Commands

### wrun site:init

- Scaffolds site into current directory
- Interactive prompts by default
- `--defaults` creates placeholder config
- MUST fail if any of these exist:
  - `index.html`
  - `work/`
  - `assets/`
  - `warp.config.json`

---

### wrun site:work

- Ensures:
  - `/work/index.html`
  - `/assets/data/work.json`
- Create-missing only
- Never overwrites HTML

---

### wrun site:project <slug>

- Creates:
  - `/work/<slug>/index.html`
- Appends entry to `work.json`
- Default: interactive prompts
- `--defaults`: TODO placeholders
- MUST fail if:
  - slug exists
  - directory exists

---

### --force

- May overwrite ONLY `/assets/*`
- MUST NOT overwrite:
  - Any HTML
  - `warp.config.json`

---

## Page Templates

### /index.html

MUST include:

- `#work`
- `#contact`

`#contact` MUST include:

- `mailto:` using `contact_email`
- GitHub + LinkedIn links

---

### /work/index.html

- Loads `/assets/js/work.js`
- Renders list from `work.json`
- Shows HTTP hint on failure

---

### /work/<slug>/index.html

- Embeds project `title` + `summary`
- Includes consistent SEO defaults
- Contains human-editable content sections

---

## Sitemap

- Static `sitemap.xml`
- Includes ONLY:
  - `/`
  - `/work/`
- Generators MUST NOT append project URLs

---

## Testing Strategy

- Slug validation
- base_url validation
- Collision safety (no partial writes)
- work.json append behavior
- `--force` scope enforcement

---

## Deployment

- GitHub Pages (repo root)
- No build step
- Compatible with Cloudflare DNS

- MUST run tests until passing.

### Phase 2: Implement `warp.config.json` creation (depends on: Phase 1)

- MUST add tests for config validation and base_url strictness.

### Phase 3: Implement scaffolding (Practical bundle) (depends on: Phase 2)

End-of-phase quality gate:

- MUST run tests until passing.

### Phase 4: Implement `site:work` and `site:project` (depends on: Phase 3)

#### Subphase 4.1: `site:work` create-missing only (depends on: 3.2)
- Task 4.1.1: Ensure `/work/index.html` and `/assets/data/work.json` exist.

  - MAY create missing files.

#### Subphase 4.2: `site:project <slug>` (depends on: 4.1)
- Task 4.2.1: Enforce slug rules and fail-fast on conflicts.

- Task 4.2.2: Metadata collection.

- Task 4.2.3: Append JSON entry to `/assets/data/work.json`.
  - MUST preserve array order.
  - MUST write stable JSON formatting.
- Task 4.2.4: Create `/work/<slug>/index.html`.
  - MUST use the same `title` and `summary` used in JSON.
  - SHOULD include human-editable content section placeholders.

#### Subphase 4.3: `--force` overwrite scope (depends on: 4.2)
- Task 4.3.1: Implement `--force` behavior.
  - MAY overwrite ONLY `/assets/*`.
  - MUST NOT overwrite HTML or `warp.config.json`.

End-of-phase quality gate:
- MUST add tests for:
  - duplicate slug rejection
  - append-only semantics
  - `--force` scope enforcement
- MUST run tests until passing.

### Phase 5: Documentation and polish (depends on: Phase 4)

End-of-phase quality gate:

## Summary

This specification defines a **boring, safe, deterministic static-site workflow** that:

- Scales via append-only data
- Protects human-authored content
- Avoids framework creep
- Separates structure from presentation
